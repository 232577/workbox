# 「这是家」联动迁移与主线验收

C++ 桌面端在功能验收后合入现有 `main`。原站联动纳入正式版验收。个人项目和团队交件沿用现版的账户、任务、文件和回执边界。

## 现版工作流程

| 方式 | 待办和绑定 | 交付与回读 |
| --- | --- | --- |
| 只登录「这是家」材料账号 | 导入本人待制作、进行中和预审退回的项目。按原站账号和任务号绑定。多个同名任务由用户核对。 | 个人项目先完成本地归档并记录待回写，再向原站提交该任务的材料状态。原站只接收状态。 |
| 同时核对办公室账号 | 按两处账号和任务核对本人负责的项目。 | 办公室接收 Word 原件并通过取件入口读回校验。确认原件一致后，再更新对应原站任务，分别显示两处结果。 |

现版操作入口和用户可见限制见 [团队交件文档](../../docs/TEAM-DELIVERY.md)。

## C++ 实现选型

- Qt Widgets 继续负责项目界面。Qt Core 提供 JSON 解码、Unicode 处理和 SHA-256；SQLite 沿用现有项目绑定和交付队列表结构。
- 原站浏览器首选 Qt WebEngine。复用现版已测试的同源操作规则、脚本隔离与身份核对。网页登录仍由用户亲自完成。浏览器无持久配置的会话方案、脚本世界和完整部署清单以 Qt 文档为准。[浏览器会话配置](https://doc.qt.io/qt-6.8/qwebengineprofile.html) · [脚本执行环境](https://doc.qt.io/qt-6.8/qwebenginescript.html) · [Windows 部署要求](https://doc.qt.io/qt-6.8/qtwebengine-deploying.html)
- 浏览器移植先采用匿名本地站点，验证凭据只留在浏览器会话、限于原站来源和身份。正式构建单独核对 WebEngine 子进程、运行库、资源和中英文包，并比较打开联动前后的启动与内存占用。

## 迁移进度

| 阶段 | 合并前的验收 |
| --- | --- |
| 原站数据和本地绑定 | 解码已核对的账户与任务快照。稳定识别有效任务号、状态和观察版本。同一批快照发现重复或不完整记录时拒绝整个结果。用既有数据库只读展示无歧义的项目绑定。 |
| 登录、账户校验和待办 | 以现有读取规则从登录页面取得当前身份，验证账号切换、原站会话撤销、跨来源跳转拒绝和本人任务范围。后台读取时保留用户原站当前操作。 |
| 导入与绑定 | 遵循当前个人模式开关和三类活跃状态。绑定以原站账号和任务号为键，对既有项目及别名、重复名称、归档、合并和历史任务逐项回归。重复读取不会生成重复项目。 |
| 交付回写 | 本地归档、交付事件和待回写项一起提交。校验同一账号、任务、标题、阶段和对应本地交付事件；提交后回读同一任务的结果。超时或状态未知时保留待核对记录，先回读再决定后续动作。覆盖团队交件原件校验。 |
| 发布验收 | 匿名端到端覆盖个人和团队两条链路。同一来源数据验证旧数据库升级、原地安装、回退及真实工作站登录和状态回读。 |

本阶段已用匿名输入验证待办解码、Python 兼容的观察版本摘要及旧库绑定。所选项目的详情显示本地保存的任务编号与账号。[原型的匿名测试画面](project-window.png)

本阶段的快照解码以现版浏览器已核对的账户和本人待办为输入。返回任务中的负责人文字只供显示，后续 C++ 浏览器接入仍需在原站会话内核对真实账号、负责人和会话变化。个人项目的导入、绑定写入和交付队列依次移植后，再进行联动验收。
