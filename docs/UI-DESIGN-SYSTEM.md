# WorkBox 桌面设计系统

目标：围绕查找项目、收进文件和核对交付，提供层次清楚、状态可信的桌面工作台。界面使用统一的产品样式，业务仍由现有 Qt 控件和服务层承担。

## 覆盖范围

| 层级 | 规范与落点 |
| --- | --- |
| 基础 | 4/8/12/16/24间距节奏，固定字号，浅深语义配色，柔和表面与边框；不通过放大窗口放大文字 |
| 导航与布局 | 稳定侧栏、清楚的页标题/摘要、上下文动作；小窗口保留操作与原生滚动 |

| 反馈 | 中性/忙碌/成功/警告/失败的文本和颜色双重表达；不能用旧成功结果代表新一轮操作 |
| 对话框 | 标题、可滚动内容、固定动作区；保留取消、关闭与线程安全，不自动保存规则 |

公共外观覆盖现有按钮、输入框、选择器、复选框、页签、表格、列表、菜单、滚动条、进度条、提示、设置卡片和标准弹窗。重点页面重排不表示每个旧业务窗口都重新设计了流程；未验收部分不能宣称完成。

## 当前项目工作台

项目页按“找到项目 → 查看实际文件 → 处理当前项目”组织。页标题、粘贴消息和收进文件入口在顶部。项目数量、搜索、状态、批次和附加筛选集中在清单内。生效的附加条件可逐项清除，选定批次后显示该批交付进度。

当前项目显示完整名称、状态、类型和批次。可直接打开工作目录，符合条件的待交付项目可进入原有的交付确认流程。修改类型和材料检查从项目菜单进入，批量修改类型保留在批量操作区。

项目清单融入中性的工作区，文件位于独立内容面。深色主题使用低饱和灰阶。常规页面标题为 21px，紧凑窗口为 18px。控件正文为 14px，辅助文字为 12px。宽窗并排显示清单和详情，分栏可拖动。工作区不足 800 个 Qt 逻辑像素时，清单和详情分别占用完整区域。点击项目或通过键盘激活进入详情，“返回项目清单”恢复阅读位置。回到宽窗时恢复拖动后的分栏宽度。

### 控件与数据外观

`control_styles.py` 集中定义按钮、文本框、下拉框和状态筛选的局部样式，避免组件库默认样式覆盖应用规则。主要操作使用青绿实底，次要动作使用透明表面；普通控件约 32px 高、6px 圆角，保留清晰的输入边界和键盘焦点。导航菜单按钮必须注册同一套样式，Qt 工具按钮与普通按钮分别补偿图标内缩。

复选框采用浅色底和细边界；禁用的已选中、半选状态仍须清楚可辨，不能与未选中的浅底混同。项目状态使用文字和语义底色表达。状态筛选保留 Fluent 的选择、键盘与切换行为，选中表面由产品主题绘制。

列表与表格以柔和的整行底色表示选中，以细轮廓表示焦点。文件数量和操作位于表头上方。文件名称用常规字重，长名完整换行，大小列右对齐。文件与目录使用同一图标库。空态、读取失败和部分不可读保留独立提示。刷新和主题切换保留选中文件、手动列宽和阅读位置。

日期保留原生日历和分段编辑，并加宽日历按钮的点击区域。全选输入或粘贴完整日期时按原值精确验证，非法输入保留以便纠正。交付页同日刷新保留正在输入的日期。

## 当前交付记录

交付页标题、筛选工具和区块标题左对齐。日期控件显示北京时间的单日，或以“全部日期”按钮表示全量日期范围。通过该按钮可返回今天或选择日期。搜索匹配项目或批次，显示撤销记录时筛选入口标明“含已撤销”。工作量与类型统计标明当前筛选范围。“导出全部”始终包含所有有效交付项目，每个项目一行。

宽窗优先把高度给项目主表。选择单个项目后可查看、收起或放大明细。上下分隔条可拖动，重新打开时恢复用户设置的比例。紧凑窗口通过“项目记录”和“交付明细”页签切换。

当前项目、交付与公共控件的改版范围见[成熟工作台改版](UI-MATURE-WORKSPACE.md)。[工作台布局对比](ui/workbench/README.md)和[控件与数据视图](ui/desktop-controls/README.md)记录此前的实现。

## 功能与安全边界

当前入口采用[项目批次标记](PROJECT-BATCH-MARKERS.md)：项目为默认页，保持原排序，用同批色号标记关联；不插组标题或重复项目。独立任务组、手工交接及任务维护入口已退役，旧数据和导出历史继续保留。下段为先前阶段记录，不能据此恢复任务组页面。

2026-11-05按用户选择统一精简入口。常用侧栏为任务组、项目、今日工作量；高级设置集中归档库、全局记录/监视、历史补录、规则、主题、帮助与更新。有待核对事项时直接显示提醒，当前核对页面保留入口到离开为止。任务组主操作突出新建、续入、交接与本组导出，维护操作仍绑定当前任务并收进二级菜单。业务状态、文件处理、统计与原配置语义保持；不新增简洁/完整两套布局。

材料检查只读取登记项目的文件元数据。缺项筛选只影响展示，不改计数。复制摘要仅由用户点击触发，不读剪贴板、不监控剪贴板、不自动上传。规则编辑使旧检查失效，关闭不自动保存。项目名按纯文本显示，长名可完整查看工具提示。

在线更新必须区分检查、下载、校验、准备安装及失败；保留现有HTTPS、SHA-256、目录一致性、恢复点和安全退出协议。新UI代码进入main不等于旧安装版更新。先验证准确提交及新冻结产物，再尝试本机升级，不覆盖其他端未提交的发布工作。

## 验收

### 上一轮界面细节与更新流程（2026-11-09 源码改进）

项目清单的标题、批次选择和批量操作归入左侧清单区域，右侧所选项目与文件独立对齐；拖动分栏时两侧工具跟随所属内容。窄窗仍直接呈现批次筛选和多选。侧栏底部直接提供“检查更新”，点击进入官方版本检查。

浅色采用柔和的中性表面，深色采用低饱和灰阶；控件、原生菜单、弹窗和输入框统一细边框、圆角与状态反馈。焦点变化不改变控件占位。项目名称、状态和批次编号按层级排版，批次采用浅色底及颜色圆点；文件大小右对齐，文件与交付表的主信息和辅助信息区分字重。文件的直接打开入口随选择出现，宽窗交付列表使用区块标题，窄窗沿用切页标签。

安装版更新窗口只呈现当前状态、版本说明和一个主要动作。用户主动打开后检查，点击“更新并重启”即授权本次下载、校验、备份、退出和安装交接；下载可取消，失败可重试。升级安装显示进度，安装后由原有校验流程重启。源码运行显示“下载更新”。这些说明描述本分支源码，安装包采用对应发布版本。

新增回归先失败再实现；现有主题/列宽/滚动/保存/关闭/更新回归保持。实际Windows Qt截图采用隔离匿名夹具，覆盖浅深、常规/窄窗、空态/缺项/成功/错误与主题切换。完整Windows及网站/仓库检查、当前SHA云端CI分别记录。冻结安装、实际本机升级及另一设备验收独立记录，不相互冒充。
