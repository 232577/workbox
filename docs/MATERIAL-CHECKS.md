# 第54版能力迁入：材料检查

任务 #15。维护者已要求把 BOX 第54版的实用功能适配进 main。本轮先做可直接使用的材料检查，不把分叉产品或数据库整树复制进来。

## 来源与取舍

参考 `t971226-alt/workbox` 归档提交 `2ad047c2d92c2f43dcc075aa2a287f0b56a07708` 中 `snapshots/box-storage-build54/` 的 `file_formats.py`、`file_families.py`、`name_patterns.py`、`material_templates.py` 及规则验证脚本。保留类型家族、关键词全部包含/顺序不限、软件名称代入、所需份数和缺项检查的行为；重新适配公共版项目查询与界面，不搬入 production/classifications 数据库。

整树替换会丢掉当前交付、合并和升级修复；只加底层函数又无法日常使用。因此采用独立纯引擎加项目右键“材料检查…”入口。目录绑定、复制归档、重命名、解压和独立材料工作台留待后续独立任务，不改现有交付规则。

## 首批行为与边界

- 每项规则包含材料名称、类型家族、份数、关键词。家族覆盖 Word、PDF、表格、演示、文本、图片、音视频及压缩包；后缀匹配不是文件内容/质量验收，不转换格式、不解压。
- 文件类型使用实际文件名的后缀，只对关键词搜索主体做Unicode归一化：全角点号/全角扩展名不能伪装为真实 `.docx`；文件名里的全角斜杠不是路径分隔符。
- 关键词用中文/英文逗号、空格、加号分隔，必须全部出现，顺序不限；匹配使用 NFKC 和大小写折叠，并忽略空白及 `_ - — ·`。`软件名称`、`当前软件名`、`{software}`、`{软件名称}` 代入当前项目名。输入空关键词表示只按类型；仅由忽略字符组成的关键词拒绝，不能变成通配符。
- 一文件由稳定 ID 标识，重复元数据不重复计数；不同路径的文件是不同份，本轮不读取内容比较相同副本。一个文件命中多项规则时列为待选择，不能按规则顺序猜测；显式选择后只能满足一项规则。
- 仅检查已登记项目的当前工作文件，缺失文件、目录行、历史 ZIP 和材料归档不满足本次材料要求。目录缺失、读取失败或截断时显示检查不完整，不以部分结果宣称已收齐。软件规则为空也不宣称收齐。
- 只有明确点击保存规则才写入 `material_check_v1:<项目ID>` 设置；打开、试改和关闭不保存。规则按项目 ID 隔离，不依赖可变项目名；项目改名后软件名占位符使用新名称。项目合并后的来源身份不能操作，不自动迁移规则。
- 结果显示匹配文件、缺项、歧义和未匹配文件；歧义人工选择只作用于当前检查，不保存隐式文件绑定。刷新文件或改变规则会清除选择。
- 不修改项目状态、交付事件、个人工作量、目录或文件。检查完成不等于业务交付；源码进入 main 不等于旧安装包已有此功能。

## 验证

源码使用入口：项目列表右键 → **材料检查…**。先选择预设或编辑规则，点击“检查 / 刷新文件”；结果中的多候选文件需明确选择。点击“保存本项目规则”才保存，关闭不会自动保存。检查窗口最小600×540，规则及结果使用原生可滚动表格。

纯引擎异常输入、Unicode、数量边界、重复与歧义先红后绿；匿名项目检查规则保存/取消、归档排除、错误快照、读取取消和菜单入口；完整 Windows/网站回归与真实匿名 Qt 窄窗/浅深主题检查。正式发布与安装仍由原发布任务独立执行。
