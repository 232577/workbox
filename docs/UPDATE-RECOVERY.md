旧版在无控制台环境中启动 PowerShell 安装助手可能立即退出而没有运行安装脚本。下载、校验和数据库恢复点可能已完成，但不能因此认为已升级。修复改用隐藏控制台的创建方式、独立的运行环境，并记录助手实际开始执行；安装完成后仍校验真实程序构建及原数据目录。

## 恢复现有安装

先备份原 data 及外部工作、归档目录。确认旧 WorkBox 已正常退出，再从官方发布页获取本构建安装包，核对下方大小及摘要，在**原安装目录**安装。不要卸载、删除 data 或重建项目，不要取消 Windows 的来源安全标记。未知发布者提示与商业代码签名缺失仍需如实告知。

旧版二进制不会因新包已下载就自动拥有修复代码；首次通过外部启动已验证安装器属于辅助恢复，不应报告为旧版无辅助在线升级成功。安装后在“检查更新”核对实际构建，保留项目、工作文件和交付历史，再确认正常启动和退出。

## 排错记录

下载缓存按次保存在当前用户的 `LocalAppData/WorkBox/updates/`。修复后的助手写入该次目录的 `install-result.json`，可区分 helper-started、installer-exited、failed、verified-relaunch-requested。没有结果文件时，不应自行假定安装已开始。不要重复运行未知状态的安装器；先检查已有进程和该次日志。

`verified-relaunch-requested` 表示已验证安装目标并请求重启，仍需观察真正的窗口和原数据；它不等于所有业务验收已完成。数据库恢复点不替代工作文件备份。
