# 在线升级设计与发布边界

软件版本保持 1.0.0，使用递增日期与修订标签识别构建。

## 用户流程

点击「检查更新」会打开窗口并查询正式版本。找到新版后，窗口显示当前构建、新构建、安装包大小和版本说明。Windows 安装版点击「更新并重启」即开始下载与校验，下载期间可以取消。检查或下载失败时可在窗口内重试。源码运行提供「下载更新」，校验通过后会显示保存位置。

文件任务或待处理的恢复事项会阻止安装。WorkBox 安全停止工作线程后，持有数据会话锁并使用 SQLite 备份 API 创建数据库恢复点，再释放窗口和锁。独立安装助手等待原进程退出，锁定并重新校验安装包，然后在原目录安装。安装期间显示进度，Windows 和安装器的提示仍可见。安装助手不会强制结束进程或重启电脑。

恢复点只保存数据库（包括软件配置），不是项目文件全量备份。安装器不删除或覆盖业务data、工作文件与历史归档；安装失败保留旧证据和下载。数据库恢复需要人工核对，不自动覆盖新业务。首次部署本机仍走现有本机完整恢复点工具。

## 信任和兼容边界

首选官网固定`/updates/stable.json`清单（由已核验的下载目录生成，不访问匿名GitHub限流接口），传输不可用时读取固定`232577/workbox` GitHub Releases HTTPS接口。拒绝草稿、预发布、非法日期/标签和不匹配的官方资产名/URL。下载仅允许HTTPS及GitHub发行CDN的精确主机名；网络超时、限额、坏JSON、无digest或错误摘要一律不安装。限定元数据1MiB、安装包256MiB，失败清理本次临时文件，完成文件使用唯一目录并保留Windows Internet来源标记。安装前再校验并保持只读文件共享锁直至安装退出，降低校验后被替换的风险。

本机制信任GitHub仓库发布权限和TLS，SHA-256用于校验公开资产一致性，不冒充独立发布者签名或商业代码签名。不会给PR代码发布密钥。当前仅支持Windows x64冻结安装版内安装；源码运行可检查和下载，但不会替换Python或源码目录。

在线升级模式固定使用已存在的原安装目录，并在写入前再次核对最终目录。普通手动安装保留目录选择。安装器成功退出后，助手使用 `--build-info --build-info-output` 探测目标程序，核对实际构建标签及原数据路径后再请求启动 WorkBox。安装退出码与探测结果一同用于核验升级。

## 验收和协作

覆盖旧/同构建、不同大版本、坏标签、错误来源、大小/摘要错误、取消、重定向、无网络、并发任务、数据库备份失败与退出失败。受影响测试和完整清单通过、原生界面与冻结EXE检查后再通过PR合入main；只从通过门槛的精确main提交构建正式包。旧资产不可覆盖，新包与官网元数据必须一致。远端已跑测试不代替本机安装和数据保留核验。

选择按需升级而非强制自动升级，是为了不打断归档/交付工作；后续若增加自动检查，需独立的可关闭配置和速率限制。
