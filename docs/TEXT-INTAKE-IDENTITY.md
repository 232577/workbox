# 文字收录：沿用已有项目，避免无提示重名

快捷粘贴、文字拖入和待核对确认，在同一写入事务中先核对完整项目名称，再创建缺少的项目。唯一同名的活动项目沿用原编号、原批次、原工作目录和现有状态；新消息不会把已完成的工作重新设成待开发，也不重置类型、加急、备注和交付历史。确认过的旧名按保留项目解析，不重新建立已合并项目。

新收件记录仍保存自己的原文和结果编号。包含新旧项目的消息只为新项目创建目录，不把旧项目搬入新批次。当前反馈说明沿用数量。名称比较只统一Unicode兼容字符、大小写和空白，不做模糊相似匹配。

已有多个同名项、已归档、已删除或工作目录待恢复时，整条消息停在待核对，不先创建其中一部分。先核对/合并已有项、恢复保护项或修正名称后，再确认。旧的显式按批次建项API仍保留，用于调用方明确建立独立批次；它不等同于快捷文字收录。

已有重名记录不会在启动或安装时自动合并。合并仍需当前预览和单独确认，保留原件与历史。待开发、待交付不是禁止合并的状态；目录重叠、文件占用、未完成归档或不兼容的跨批次合包等保护不能靠改方向绕过。

改名/合并预检拒绝时，数据目录的 `project-preview-failure.json` 保存最近一次原因、项目编号、当时状态和时间，不保存材料内容。成功或取消的预览不覆盖该诊断。日志写入失败不放行原本被阻止的操作；业务数据库和恢复日志不因此改变。

本次修复在匿名夹具覆盖文件先到、文字先到、改写消息、待核对期间建项、名称边界、已合并旧名、混合批次和两个合并方向。历史案例未保留的预检失败原因不能凭最终成功记录推断。
