## 已确认的问题与处理

| 问题 | 实际入口与影响 | 处理 |
| --- | --- | --- |
| 人工确认 ZIP 时，读取校验结束到提交之间文件可被替换 | 项目确认交付 → 控制器 → DesktopService → WorkBox.confirm_delivery → 数据库追加交付 | Windows 复用只读 ZipLease，保持到数据库事务提交结束；取消、内容不符和数据库异常均释放文件，失败不追加交付。非 Windows 保留原有读取接口 |
| 普通文件复制中强退，半成品会出现在工作文档并进入材料交付 | receive_file → copy_verified → 重启 → 项目文档/材料交付 | 暂存名采用现有消费者共同排除的 `~$workbox-….partial`；保留中断现场，正常重试完整发布原目标文件名，不把碎片算作材料 |
| 导出交付表的保存窗口未占用工作槽 | 今日交付 → 导出全部 → 原生保存窗口 → FileJob | 保存窗口期间加入业务忙碌状态；关闭或退出后使旧请求失效；取消和错误释放工作槽，仍能重开页面并重试 |
| 材料归档复制强退后，暂存残片让重试持续失败 | 确认材料交付 → 已登记未完成 attempt → 最终目录完整性检查 | 复用安全遍历核对全部文件；清单内文件保持一致且仅多出新旧暂存格式时，保留原 attempt 和目录，改用独立副本重试 |

归档重试仍拒绝未知文件、已修改文件、占用和目录联接；已经登记完成的归档不能借此另建副本绕过校验。最终数据库完整文件集合检查没有放宽。暂存文件名不是所有权证明，不据此删除任何残留。

当前启动链是 `main → FloatingController → CompactPanel`。受控源码、脚本、构建配置和导入检查均未发现旧 `MainWindow`、`CaptureDialog` 或 `TaskGroupsPage` 的运行入口，因此移除了这三类页面及它们独占的表格辅助函数、导入和测试。`ui.py` 保留 FileJob、label、button、human_size、app_icon 的原接口及实现，当前调用方无需改名。

删除的测试只覆盖退役页面；现有主窗口、消息收录、任务后台、历史数据、交付导出及窗口退出检查继续保留。英文 Windows 区域设置测试继续验证当前文字和文件收录入口，移除旧 CaptureDialog 分支。没有删除任务组的数据库表、后台接口或历史导出附表。
