## 用户可见的区别

| 方面 | GitHub 当前 main | 本地 BOX 构建 54 | 迁移处理 |
| --- | --- | --- | --- |
| 主要用途 | 项目开发、文件收件、交付、工作量与归档 | 按软件收纳材料、规则匹配、目录绑定与收齐统计 | 先确定两个工作台的关系，保留公开项目能力 |
| 状态 | 待开发、开发中、待交付、已交付；类型和加急独立 | 材料缺失、已收齐等收纳状态；收纳不要求核对或提交 | 收纳状态与项目状态分别建模，不互相冒充完成 |
| 规则 | 项目匹配、项目类型和文件数等设置 | 类型家族、所需份数、每份关键词、软件名称自动代入 | 提取纯匹配逻辑，再对接现有项目服务 |
| 类型家族 | 现有收件和归档能力 | Word、PDF、表格、压缩包等类型家族，同类多个后缀可满足要求 | 审查后缀映射和兼容性，不把扩展名等同于文档内容验证 |
| 保存路径 | 已登记项目的工作目录 | 每个收纳目录绑定一种规则；规则可绑定多个目录；每个软件独立子目录 | 增量增加目录绑定，不迁移已有文件 |
| 首次/未匹配收件 | 现有项目收件流程 | 先预览软件、规则、文件与路径；未配置目录时确认后再建立并绑定 | 多候选、未匹配和冲突保持明确选择 |
| 手动建立的目录 | 无本地新版的目录绑定界面 | 用户选用该目录时才识别未绑定状态，不递归后台导入原有内容 | 保持用户主动选择与取消无副作用 |
| 压缩包 | 原件和归档 basename 保留；不解压或执行 | 可只保存原包；另有明确选择后的解压分类入口 | 原包收纳先迁移；解压需单独设计、审查并改变现有产品约定后才实现 |
| 界面 | Fluent 项目/文档工作台、嵌入交付记录 | 紧凑材料清单、软件分组、淡绿色展开入口、今日收录与分类统计、精简右键详情 | 统一现有风格，不替换整个主窗口 |
| 桌面入口 | 现有悬浮和托盘生命周期 | 金属图标、悬浮球双击、空闲贴边等独立改动 | 单独 PR，保留公开版退出和线程安全回归 |
| 升级 | 现有安装器和可追溯发布流程 | 免安装包清单更新、保留数据更新、独立空数据运行 | 不把本机更新机制直接替换公开安装器 |

以上本地功能根据构建 54 源码及本机留存验证结果整理；本次未重新进行其原生交互验收。

## 不能整目录覆盖的原因

公开 main 有本地快照未包含的能力：项目改名和确认合并、项目别名与目录变更、默认项目类型和交付类型统计，以及文档列表延迟排版滚动修复、非中文 Windows 区域兼容回归。协作指南、仓库安全 hooks、CI、发布规程和网站维护也持续发展。

以当前公开树全部 262 个被跟踪文件，对照本地构建附带的源码快照：92 个共同文件内容相同，92 个共同文件内容不同，78 个公开文件在本地快照中缺失，本地快照另有 220 个路径。计数含测试、网站和文档，不能当作待导入或待删除清单。部分同名模块的数据库与服务实现已明显分叉。

直接替换 `database.py`、`desktop_service.py`、`ui.py`、`workspace_manager.py` 等共享模块，可能删除公开版迁移和业务行为。不能因为本机收录测试通过，就推断旧公开项目和交付历史兼容。

本地 `requirements.txt` 与锁文件也不完全同步：前者声明了压缩包相关库，锁文件尚未列出相同集合。迁移压缩包能力前必须建立完整可复现依赖，并验证相应许可及打包来源，不能沿用本机虚拟环境证明干净安装可用。

## 建议的 PR 拆分顺序

1. **明确产品边界与接口。** 在公开 main 上定义收纳规则、目录绑定和材料收齐的概念。项目状态、不可变交付事件、类型统计、撤销/恢复和现有路径保持既有语义。确定材料工作台入口，再开始功能实现。
2. **纯匹配引擎。** 迁移类型家族、软件名称与关键词匹配，先提供匿名回归。逗号、空格、`+` 分隔的多个关键词按既定“全部包含、顺序不限”语义测试；同类型多份不能重复消费同一文件；多候选必须人工选择。该步不复制文件、不改 UI、不写业务数据库。
3. **规则及目录元数据。** 在公开数据库上增加向前兼容迁移，以稳定规则 ID 绑定目录；一目录一规则、一规则多目录。规则改名保留关联，停用/删除不从快照复活。目录缺失或冲突提示选择，不静默重建或重绑。
4. **确认收录与实际复制。** 用户确认前不建立业务目录、绑定或任务。唯一有效绑定自动推荐；多目录需选；无绑定先确认上级位置和目录名。软件文件夹与文件名默认软件名称，保留原后缀。原件不动，复制校验、同名新建/覆盖、重试和历史完整性分别测试；旧项目继续固定原路径。
5. **工作台 UI 与统计。** 在既有 Qt 结构中加入紧凑软件分组、淡绿色展开入口和收录明细。收录材料份数、涉及软件数、首次有效交付项目数分别命名和计算；不把收录统计冒充交付工作量。保留文档列表滚动、选择与后台线程修复。
6. **可选桌面和发布改动。** 金属图标、悬浮行为、免安装升级和解压分类分别评估与验证，不混进核心收纳 PR。发布仍只来自合入并通过检查的准确 main 提交，不修改已有标签、安装包或网站下载地址。

各步从公开仓库任务分支开始，逐模块适配；保留公开版未涉及文件，不复制本地 AGENTS、网站、历史验证报告或整个开发目录。数据库重构和桌面工作台不得通过“只新增文件所以安全”来代替兼容验证。

## 验证门槛

- 本地构建 54 留存结果为 114 项相关回归通过、实际冻结程序 114 项检查通过；更新后 16 张选定业务表及材料内容保持。这是该构建的历史证据，不是当前 main 或未来合并代码的测试结果，也不是全历史测试全通过。
- 每个功能 PR 先增加会失败的匿名回归，再实现；执行受影响与完整 Windows 测试清单，明确失败、环境跳过和警告。
- 数据兼容使用匿名旧版数据库夹具，覆盖项目别名/合并、交付与撤销、统计、已登记路径及目录绑定迁移；不读取真实用户数据库。
- 界面改动提供真实 Qt 截图，并验证窄窗、浅/深色、键盘、取消、多文件、多目录和滚动定位。生成示意图不能替代软件截图。
- 新依赖在干净环境安装；冻结构建和更新另行验证。Git 仅提交公开源码、匿名测试与文档，不提交安装包、数据库、材料、备份、私有截图、凭据或本机路径。
- 保留仓库边界检查、网站检查及四组 Windows CI；通过后才审阅合并，另按发布规程决定是否构建发布。
