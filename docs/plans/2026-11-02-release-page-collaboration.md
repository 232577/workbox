# 发布页与多机协作

## 目标和边界

参考 Filee 官方中文站（2026-11-02 实际浏览）的浅色柔光背景、大标题、双栏交互首屏、分区演示和清晰下载入口，重新组织 WorkBox 发布页。保留 WorkBox 标志、绿色主色、真实截图、历史教程标识及准确功能说明；不复用 Filee 的代码、品牌或产品素材。网页演示只使用固定匿名示例，不读写真实文件，不上传项目资料。

采用现有静态 HTML/CSS/JavaScript 与 Worker，不引入前端框架。保留原下载地址、所有历史安装包、统计鉴权和关闭的赞助配置。桌面主程序、正式数据、归档与安装不变。

## 协作决策

以公开仓库 `232577/workbox` 为唯一可协作的产品源码基线。每个地点从同一远端克隆，任务使用独立分支；禁止再将某台机器的整个源码快照覆盖 main。旧开发目录保留历史与私有验收资料，不推送旧开发历史。新规范采用 PR、状态检查、快速前进同步、主分支保护及不可改写的发布标签。当前只有同一所有者，不虚构第二位审阅者或要求无法完成的自我审批。

替代方案：只换主题颜色达不到参考页面的结构目标；整体照搬参考站会错误表达产品能力；继续单机导出会覆盖其他地点的更新。因此采用原生页面重组与统一 Git 历史。

## 执行与验证

- [ ] 页面与示例交互先写失败测试，保留下载、无脚本、键盘、主题和移动布局。
- [ ] 添加仓库边界检查、协作命令、CI、贡献指南与发布追溯约定，并以隔离仓库测试脏树、错误远端和分支分歧。
- [ ] 独立分支推送并创建 PR；实际运行 CI 后配置和核验服务器端保护。
- [ ] 本机浏览器验证新页面；只从已合并的准确提交部署本站，下载字节和历史资产不变。
- [ ] 记录结果、未验证边界和新旧本地目录用途；不删除用户私有资料。

## 风险检查

不把 Git 代码协作称为业务数据云同步；不把网页示例称为真正的文件收录。自动检查不接触生产数据，不向外部 PR 提供发布凭据。主分支更新必须先获取远端并处理冲突，绝不自动 reset、强推、stash 或丢弃他人改动。所有发布标签保持原目标，安装包仍由实际摘要确定。
