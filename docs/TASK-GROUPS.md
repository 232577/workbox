# 任务组、材料就绪与人工交接

主窗口新增“任务组”，默认跨日期显示未结组。粘贴项目消息或点击“新建任务组”会生成如 `G20261105-003` 的组号，组内任务号如 `G20261105-003-02`。编号按北京时间分配，排序、改名、撤回不重排；组色保持稳定，状态仍用文字表达。

“添加消息”明确续入当前组。同组同项目的未结任务复用，原文逐条保留；“新一轮任务”用于新的要求，沿用项目身份和目录但建立新的本次任务。重复原文默认定位已有收件，不会重复创建；明确新一轮可以使用相同原文。已知内部任务号的原样清单回贴会核对名称和组归属，未知编号或冲突进入待核对，不把任务号当项目名。

材料就绪沿用现有有效交付规则。旧项目的历史交付不会自动满足新任务；一个新交付只对应唯一明确待办时可自动关联，多个候选时需选择。用户也可以明确关联非空归档位置的旧有效交付，空位置的旧状态记录不能充当本轮材料。

发给对方后，选中任务并点击“记录已交接”。确认框列出任务号、项目及确切关联归档；后台若换成了新版本，旧确认会拒绝，不误记新版本。此操作只记录人工确认，不发送任何文件，不读微信。交接、撤销交接、任务撤回、重开与移组留存动作记录，详情可按北京时间查看。

交付记录被撤销、恢复或换绑后，旧交接不会自动复活。原交接历史仍保留，当前结果需要再次核对。原范围需返工可“重开任务”，新范围使用新一轮；二者均不删除历史交付。项目合并仅归一项目身份，不自动合并两条任务。

组头显示总数、材料就绪、人工交接、待交接、待核对与撤回。待交接（已确定）与待核对互斥；筛选“仅未交接”不会缩小组总数。已结清、全部撤回和待核对不是同一状态。项目原有首次交付工作量独立计算，不因多轮任务而重复计数。

更多菜单的“复制本组未交”只复制所选组；需要跨组清单时，在“高级任务操作”使用明确的“复制当前筛选的全部未交清单”。复制仅在用户点击时发生。任务组底部直接提供“导出本组表格”；交付记录页的“导出表格”仍是全部有效交付项目。工作簿包含交付项目、类型汇总、任务组汇总、任务明细四张表，本组导出默认打开任务明细。任务项数与去重项目数分开。

历史收件可从“高级设置”预览后明确导入。补录保留各消息原时间和项目来源，显示“历史补录”；没有充分证据的本次完成不自动认定。旧项目、物理批次、工作目录、文件名和交付事件保持。编号唯一范围是当前工作箱数据，恢复旧库或将来跨设备合库需先核对编号冲突，不支持直接覆盖数据库后假定外部引用仍唯一。

归档分类规则可从“高级设置”进入主窗口配置。按最近有效交付的单项目归档文件数判断；默认阈值4，对应“可运行/生成材料”，数量未知保留原类型。它与ZIP自动交付阈值独立，可改目标类型和阈值。规则、预览、应用与撤销各自有明确入口；旧分类撤销不会覆盖之后的自动变更或人工选择。

干净安装的新分类规则默认关闭，不含个人配置；本用户已授权的既有数据调整与后续默认开启在备份、安装和核对后单独执行。升级不自动把旧消息全部标已交接，也不重写原项目、交付或目录。
