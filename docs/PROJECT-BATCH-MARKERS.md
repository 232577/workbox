# 项目列表批次标记

工作台沿用原项目状态和排序。批次颜色、编号和交付进度在项目清单内查看，全部交付表仍可导出。

## 使用方式

- 启动、粘贴收件和反馈定位回到项目工作台。移除任务组导航、独立页面、手工交接与按任务/按组维护入口；不另造一个同样的任务组弹窗。
- 仍按原有待开发、开发中、待交付、已交付筛选与原排序呈现，一项目一行。没有分组标题、不重复项目行、不按颜色重排。
- 每行显示批次色标及紧凑编号，编号后显示“余N”。有有效项目且已全部交付的批次显示“已齐”。项目名仍完整换行，色标与行选择、焦点分别显示。
- 多批归属最多并列两个编号，其余用“+N批”表示。极长的首枚编号可在中间省略，工具提示和无障碍说明提供每批完整编号以及“已交付X/Y，剩余Z”。
- 选择一个批次后，清单筛选下方显示该批摘要。选择“所有批次”时收起摘要。整批有效项目为零时显示“本批无有效项目”。统计字段缺失时只显示批次编号。
- 批次筛选与编号搜索使用同一收件关系；原目录批次不被改写。批次编号是本机工作箱标识，颜色为辅助，不能只用颜色判断归属。

## 只读归属

项目原有batch_id是建项/目录身份，不能代表后来的整批收件。只读索引合并以下依据：

1. 已有任务记录的当前组归属，使用canonical项目身份及最近移组动作，保留原组代码/颜色；不读取或推算交接状态来决定项目状态。
2. 未被已有任务消息覆盖的committed收件回执，使用完整project_ids（包括复用项目），按canonical项目去重；覆盖过的回执不能把已移走项目拉回旧组。
3. 按每个原项目（包括已合并来源）分别检查：自身无上述依据时，回退其真实原建项批次，再按合并后的身份汇总去重。另一成员的收件或任务依据不能遮住它的原批次；同一原项目已有有效收件/任务依据时，不额外重复显示建项批次。

改名合并后保留双方有效来源，连续合并同样适用；清单、批次筛选和表格导出共用这些归属。此前合并后被遮住的原建项批次在使用新索引刷新时恢复，无须重做合并或修改历史数据。每批仍按最终项目身份只计一次，新增日期沿用保留项目自身的原日期。

一个项目可以关联多批。索引不创建组、不导入历史、不更新batch_id、不移动目录、不修改状态。读取使用固定数量的批量查询，项目与标记在同一读事务内取得；损坏/缺失来源明确提示，不制造批次。

既有组编号保持。普通收件以R加日期/回执ID生成稳定完整编号，原建项回退以B加日期/ID生成编号；紧凑显示保留类型前缀和日期/编号，完整信息可查看。未知日期明确为未知，编号仍以既有ID稳定标识，不编造日期或每日顺序。单个项目颜色与编号的变化不得改变它的项目ID和文件目标。

每批按合并后的项目身份去重，以当前项目状态统计已交付和剩余数量。已归档项目仍计入，已删除项目在恢复前不计入。搜索、状态和其他筛选只改变清单显示范围。交付、撤销交付等状态变化会在工作台刷新时更新同批余量。个人工作量资格与首次交付日期各有独立口径。

## 状态、收件与历史

普通文字入口使用已有receive_text流程，不再自动新建任务组或本次任务；同名项目沿用原身份和当前状态。旧任务编号格式的消息需要核对，不能将编号拼进新项目名误建目录。含歧义的消息仍进入待核对。

移除task_groups_ui的运行时入口；已有任务、交接、来源及动作表保留，历史后台接口和只读导出兼容。全部交付表仍按项目去重，不改变首次工作量、有效性及代交语义；在项目表补充与界面一致的收件批次编号，旧历史附表保留为既有记录，不由本轮自动补造。

## 验证边界

匿名夹具覆盖同批跨状态、原排序、文件先建项再整批收件、多个批次、旧组移组/合并、旧库无任务表、无依据/坏来源、只读一致事务、千级数据无N+1；实际Qt检查浅深/窄窗、标记、选择/右键/双击/全选/滚动、粘贴后查看和全部导出。现有数据通过既有恢复点机制保护，升级不得删除或重分类真实记录；新发布保留旧标签/资产。
