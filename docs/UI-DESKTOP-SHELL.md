# 横向工作台与组件改版

模式为 Operate。用户已明确拒绝既有外壳，要求参考成熟项目并继续功能交付；这轮替换视觉结构，业务规则保持。

参考 [Files](https://www.files.community/) 的命令区与文件平面、[GitHub Desktop](https://docs.github.com/en/desktop/overview/creating-your-first-repository-using-github-desktop) 的对象上下文和分栏、[WinUI Gallery](https://github.com/microsoft/WinUI-Gallery) 的控件状态。借鉴结构和交互，不引入它们的业务或复制品牌资源。

原生标题栏下是紧凑的横向工作区导航，品牌、项目、今日工作量和条件性待核对入口在一行，设置位于末端。保留可访问文字、完整数量、键盘与原生菜单，取消常驻空白侧栏。页面命令区集中搜索、收件和当前作用域筛选，不再在清单里重复堆叠标题。

宽窗默认项目清单约 360px，文件工作区取得剩余空间，分隔条仍可拖动且保留人工比例。窄窗清单与详情各占全宽，返回恢复阅读位置、选择和焦点。长名称按需换行，项目状态、类型和批次保留，普通行提高信息密度而不固定裁切长名称。

组件采用两层中性表面、细分隔、统一图标和控制尺寸。正文 14px、辅助 12px、对象标题 18px，常用控件约 32px。主动作、悬停、按下、禁用、选择和键盘焦点分别表达；浅深色与实际中文字体均需截图核对。不加虚构统计、大面积装饰和无业务意义的渐变。

名单导出由另一端 PR #54 提供，本轮从最终主线整合，保持只导出全部日常待开发 canonical 项目名称、无写库副作用的契约。测试核对新布局中的入口、保存取消/覆盖/失败、忙碌关闭与原交付导出并存。

验收覆盖 1200×780、660×480、浅深主题、长名、筛选清除、批次进度、分栏和列宽、Tab/Enter、日期、未知/部分/上次读取状态。源码通过完整 Windows 四组后才合并；冻结构建、匿名安装与本机实际安装另行核对，不把源码截图当成已安装结果。
